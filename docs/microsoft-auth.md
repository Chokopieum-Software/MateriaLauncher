# Вход Microsoft в Windows

Ответ браузера принимается по `msal706fbc67-be98-4ded-bbe7-cc50097e2e2d://auth`.
Этот адрес должен быть разрешён в регистрации приложения Microsoft с client ID
`706fbc67-be98-4ded-bbe7-cc50097e2e2d` как redirect URI для публичного/native клиента.
Регистрация протокола в Windows не заменяет настройку приложения в Microsoft Entra.

Установщик Inno Setup предлагает включённую по умолчанию опцию регистрации URI
для входа Microsoft. Обработчик записывается для текущего пользователя и сразу
указывает на установленный EXE. При удалении программы он удаляется только если
всё ещё указывает на эту установку; обработчик другой копии или IDE сохраняется.
Если снять опцию, обработчик можно зарегистрировать при первом входе из лаунчера.

При нажатии Microsoft проверяется обработчик в `HKCU\Software\Classes`.
Если его нет или команда указывает на другую копию лаунчера, программа предлагает
регистрацию для текущего пользователя. Отказ прерывает вход без изменения реестра.
Установленная сборка использует `jpackage.app-path`; запуск из IDE/JAR — Java и
абсолютный classpath текущего процесса в манифесте вспомогательного JAR в `auth-launchers`.
Команда в реестре содержит только Java и путь к JAR: полный classpath
не раздувает команду обработчика Windows.
После перемещения программы настройка
предлагается снова.

Вход использует MSAL4J, Authorization Code + PKCE S256, случайный `state` и выбор
аккаунта в браузере. Процесс, запущенный по URI, передаёт ответ ожидающему процессу
через локальный TCP-сокет и завершается до инициализации интерфейса и логирования.
HTTP callback отсутствует. Ожидание ограничено тремя минутами.
Windows ShellExecute нормализует адрес, добавляя `/` после `auth`.
Обработчик принимает оба варианта (`://auth?…` и `://auth/?…`), проверяя адрес и `state`.
В MSAL4J 1.26.0 `ResponseMode.QUERY` заменяется библиотекой на `FORM_POST`, поэтому
`response_mode=query` задаётся через `extraQueryParameters`; это покрыто тестом.

Кеш MSAL шифруется AES-GCM, ключ хранится в Windows Credential Manager через
java-keyring. Это обходит ограничение размера одной записи Credential Manager.
Старый кеш из keyring переносится при следующей записи. Связь UUID Minecraft
с конкретным аккаунтом MSAL также хранится в keyring.
Minecraft access token используется только для текущего запуска и не записывается
в SQLite или журнал команд. Старые значения в таблице Accounts очищаются при
загрузке AccountManager. Старым профилям без связи с MSAL потребуется повторный вход.
Повторный вход обновляет существующий профиль по UUID, включая изменившийся ник.

Выход очищает кеш и все Microsoft-профили лаунчера. Браузерные cookies Microsoft
не удаляются; следующий вход всё равно открывает выбор аккаунта. Старые офлайн-профили,
созданные предыдущей версией при ошибке входа, автоматически не удаляются: в базе
нет признака, позволяющего отличить их от вручную добавленных профилей.

## Ручная проверка с настоящим аккаунтом

1. Установить EXE со снятой опцией регистрации URI и без существующего обработчика,
   нажать Microsoft. Отказаться от настройки:
   браузер не открывается, реестр не меняется.
2. Повторить и разрешить настройку. После входа в браузере разрешить открытие
   Materia Launcher: второй интерфейс не появляется, профиль добавляется.
3. Повторить вход в тот же аккаунт: запись обновляется без дубликата.
   Добавить другой аккаунт: браузер предлагает выбор.
4. Перезапустить лаунчер и запустить игру: сессия обновляется для выбранного UUID.
   Проверить, что в БД нет Minecraft-токена и в логах нет команды с токеном.
5. Проверить отмену входа, истечение ожидания, отсутствие Minecraft-профиля,
   недоступность Xbox/Minecraft: показывается ошибка, офлайн-профиль не создаётся.
6. Выйти из Microsoft в настройках: профили исчезают, следующий вход открывает браузер.

Автоматические тесты не открывают браузер и не изменяют Credential Manager.
Тест регистрации Windows создаёт временный ключ в `HKCU\Software\MateriaLauncherProtocolTests`,
проверяет сохранение кавычек, кириллицы и длинной команды, затем удаляет ключ.
Регистрация самого протокола проверяется через Unicode Windows API без `reg.exe`.
